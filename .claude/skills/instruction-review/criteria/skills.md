# Skill criteria

Apply alongside [shared criteria](shared.md).

## Discovery and compatibility

Will the intended host discover and load the skill? Check its location, name,
frontmatter, and supported fields against the applicable specification and host.
Separate required metadata constraints from recommended body size or style. For
mirrored entry points, check that they select the same shared behavior.

## Activation scope

Does the description identify the intended requests and distinguish nearby
requests outside scope? Assess activation separately from execution quality. Use
actual loading evidence for activation claims; untested descriptions warrant
uncertainty, not a claim of failure. Wording preferences are hypotheses to test.

## Workflow and progressive disclosure

Does the body provide a coherent workflow and specify when references are
needed? Keep essential constraints reachable before their affected actions.
Inspect resource paths, reference chains, and prerequisites. Flag unconditional
loading or fragmented guidance when it causes avoidable work or missed
requirements.

## Behavioral value

Does the skill contribute domain knowledge or a procedure beyond generic advice?
For claimed improvements, look for representative outcomes compared with no
skill or the previous version. Do not treat structural validity as proof of
usefulness or require executable automation for an agent-led workflow.
